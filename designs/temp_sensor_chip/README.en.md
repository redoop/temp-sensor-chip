# temp_sensor_chip — mpc-frame design

[中文](README.md)

This is the mpc-frame-adapted version of `temp-sensor-chip`. It puts the chip's
**complete digital path** onto `FrameTop`'s 66-bit bidirectional payload
interface and ships with an end-to-end functional test.

## Files

| File | Purpose |
| --- | --- |
| `rtl/TempSensorTop.sv` | Top-level module (fixed 5-port Frame contract) |
| `rtl/frame_bridge.sv` | Pad input sampling (`t2f_in` / `scl` / `sda`) |
| `rtl/temp_engine.v` | Piecewise-linear conversion engine (from chip RTL) |
| `rtl/temp_regs.v` | Register file (from chip RTL) |
| `rtl/i2c_slave.v` | I2C slave (from chip RTL, see fixes below) |
| `tests/t2f_model.v` | Analog front-end behavioral model (ngspice-fit curve) |
| `tests/i2c_master_model.v` | I2C master BFM |
| `tests/include/t2f_model_params.vh` | Auto-generated calibration constants |
| `tests/TempSensorTopTb.sv` | Unit test (no FrameTop) |
| `tests/FrameTempSensorTopTb.sv` | Frame integration test |
| `design.json` | Build tool configuration |

## Pin Mapping

Payload bit `n` maps to `user_io[n + 7]` (the low 7 bits carry the design ID).

| bit | user_io | Direction | Signal | Notes |
| --- | --- | --- | --- | --- |
| 0 | 7 | input | `t2f_in` | Temperature-to-frequency pulses, driven push-pull externally |
| 1 | 8 | input | `scl` | I2C clock; this slave never stretches it |
| 2 | 9 | inout | `sda` | I2C data, wired-OR open-drain |
| 3 | 10 | output | `os_int` | Overtemp alert, open-drain (`oe=1` pulls low) |
| 4 | 11 | output | `shutdown` | Measurement gate, push-pull |
| 5 | 12 | output | `heartbeat` | Activity indicator, toggles every cycle |
| 6+ | 13+ | — | — | All released |

**Inputs and outputs must use different payload bits**: the external analog
front-end drives `t2f_in` push-pull, so sharing a pad with the open-drain
`os_int` alert would short the pulse source against the alert pull-down.

## Contract Details

* **Reset polarity**: Frame's `design_reset` is active-high
  (`reset | ~selection_valid | ~design_selected`). The chip RTL is active-low,
  so the top derives `wire rst_n = ~reset;` for its submodules.
* **Single driver**: the whole payload bus is driven from one `always_comb` in
  the top level, and unused bits are explicitly released with `io_oe = 0`.
* **SDA wired-OR**: the slave's drive direction is exported as `sda_oe` and
  mirrored onto `io_oe[2]`; the bus value `sda_bus = sda_oe ? 0 : sda_i` is
  resolved inside the design so the slave never samples a floating node.
* **10 MHz requirement**: `GATE_CYCLES` (100000) and the calibration table
  assume a 10 MHz clock and a 10 ms gate window, so testbenches must keep
  `CLK_HALF = 50ns`. Changing the clock rescales the raw pulse count and
  invalidates the calibration.
* **Calibration source**: `tests/include/t2f_model_params.vh` is generated by
  `scripts/gen_t2f_model.py` from the ngspice characterization. The unit test
  feeds it to both `t2f_model` and the design under test, so the model and the
  lookup table are guaranteed to agree.
* **No `timescale`**: no source carries a `` `timescale ``, matching mpc-frame's
  own modules, so the mixed compile raises no `TIMESCALEMOD`.

## Two Fixes to the Chip RTL

`rtl/i2c_slave.v` differs from the chip original in two ways, both required to
make the design usable on a shared bidirectional pad:

1. **`sda_oe` is exported** (new output port). The original kept it internal,
   so an integration wrapper could not know when the slave pulls SDA low and
   therefore could not drive `io_oe[2]` to pull the shared pad down.
2. **Address acknowledge fixed.** The original only ever assigned `addr_ok = 0`,
   so the slave NACKed *every* address, including its own. The chip's own
   testbench only checked that a wrong address is NACKed, never that the correct
   address is ACKed, which is why this went unnoticed. `addr_ok` is now latched
   at the end of the address byte as `addr_ok <= (rx_shift[7:1] == I2C_ADDR)`.

## Test Flow

```sh
make check DESIGN=designs/temp_sensor_chip
make trace DESIGN=designs/temp_sensor_chip
make wave  DESIGN=designs/temp_sensor_chip
```

`make check` runs lint, the unit test and the Frame integration test. Both tests
close the same loop:

```
t2f_model (analog front-end model) -> t2f pad -> design
  -> temp_engine (10 ms gated counter + piecewise-linear table)
  -> temp_regs -> i2c_slave -> pad -> i2c_master_model read-back
```

**Unit test** (drives the payload pads directly) covers:

| Check | Result |
| --- | --- |
| Payload bus state during reset | PASS |
| Temperature read-back at 25, −40, 0, 85, 125 °C (±1 LSB) | PASS |
| TOS / Thyst default read-back (0x64 / 0x4B) | PASS |
| TOS / Thyst write-through | PASS |
| Own address 0x48 ACKed, foreign address 0x50 NACKed | PASS |
| `os_int` pulls low above TOS | PASS |

85 °C reads back 169 instead of 170 (+0.5 °C), inside the ±1 LSB tolerance and
expected from piecewise-linear rounding.

**Frame integration test** (everything through `user_io` / FrameTop) covers:
design-ID selection, the push-pull `shutdown` output, `heartbeat` toggling, and
closed-loop temperature read-back at 25 / 125 / 0 °C with `os_int` asserting and
releasing on the Frame pad.

> Note: `make check` builds with Verilator `--binary` (2-state), where a `1'bz`
> literal collapses to `1'b0`. Tests must therefore not use `=== 1'bz` to detect
> a released pad; the Frame test instead checks that the pad carries a clean 0/1
> and that it toggles.

## Requirements

Verilator 5.050 (the build checks the version). The Frame test asks the build
tool for a free ID and generates a temporary registry under `build/`; the
committed `designs/registry.json` is never modified.
